# Session 1: Domain context and submission pitfalls

**Date:** 2026-11-14
**Result:** first submission (unchanged sample) scored a public score of 1.00000, the baseline.

## What the competition asks

The goal is to rewrite known fault-tolerant quantum circuits so they use fewer qubits and fewer Toffoli gates while computing the same thing. On a fault-tolerant machine, Toffolis cost time and error-correction overhead, and qubits cost hardware.

**Verifiable** means you submit a circuit file, not a claim. The official verifier runs your circuit on test inputs seeded from a hash of the circuit and checks three things:

- the output is within tolerance
- every input register comes back unchanged
- every ancilla (scratch qubit) ends clean

A circuit that fails any check fails.

**kickmix** is a simulator from Google's Qualtran library for running reversible circuits on classical inputs. Circuits are `.kmb` or `.kmx` files.

## The three tasks (cost: lower is better)

| Task | Field | What it computes | Cost | Notes |
| --- | --- | --- | --- | --- |
| invsqrt | Fusion energy | A phase based on 1/sqrt(x) for every x up to about 3.1 million, within 2^-24 relative error | qubits × Toffolis (Q and T counted per shot) | My target task: one 22-qubit input register `x`; the sample uses 260 qubits and 62,160 ops |
| dqi | Optimization | A reversible Reed–Solomon decoder | repetitions × qubits² × Toffolis | Qubits are squared, so freeing qubits pays most |
| dfthcsos | Chemistry (FeMoco) | A block encoding of the molecule's energy | normalization × Toffolis × qubits, with accuracy limits | Each ANGLE circuit is capped at 128 qubits |

## Session check: answers

1. **invsqrt cost and reference:** cost = qubits × Toffoli-equivalents, both per shot. Confirmed by running the local verifier on the sample circuit: 260 qubits × 7,987.59 Toffoli-equivalents = **2,076,774.23**, matching the reference.
2. **Overall score:** the geometric mean of each task's improvement relative to its baseline (Evaluation page). Higher is better. Improving one task with the other two at baseline still raises the total.
3. **If one task fails verification:** the whole submission is rejected. The metric verifies every task once per leaderboard split, each with its own secret salt, and any failure rejects everything.

## Submission pitfalls

From the public "VQCC submission pitfalls" notebook, which reads the official metric:

- The zip needs **exactly one** `invsqrt.kmb`/`.kmx`, one `dqi.kmb`/`.kmx` and one `dfthcsos/` folder, searched recursively. No backup copies anywhere in the zip, and never the same circuit in both formats. A top-level folder around everything is fine.
- Every submission needs all three tasks. To improve invsqrt only, submit my invsqrt with the sample circuits for the other two.
- `dfthcsos/` needs `angle_k_0` … `angle_k_<n-1>` with no gaps, plus exactly one `submission.npz`.
- The largest qubit or bit id in any circuit must be below 699,050. The local verifiers don't check this; the metric does.
- Regular files only: no symlinks or hardlinks.
- A local PASS uses different tests than the salted leaderboard runs. It's strong evidence, not a guarantee.
- The invsqrt verifier's `--shots-per-x` must be a multiple of 64.
- `kickmix.so` only loads on CPython 3.13, x86-64 Linux. Work in Kaggle notebooks.
- Scoring takes about 45 minutes. Don't submit in the last hour before a deadline.
- Before every real submission, run the pitfalls notebook on the `submission.zip`.

## How the first submission was made

1. New notebook from the competition's Code tab (data attached automatically), kept **private** so the sample circuits aren't published.
2. One cell zipped `sample_submission/` to `/kaggle/working/submission.zip` (70 MiB).
3. Save Version → Save & Run All (Commit).
4. Submit Prediction → Notebook → Version 1 → `submission.zip`.

## Verifier run on the sample invsqrt circuit

| Field | Value |
| --- | --- |
| status | PASS (770 s on Kaggle CPU, default shots) |
| score (cost) | 2,076,774.23 |
| num_qubits | 260 (22 are the input `x`; 238 are ancillas) |
| toffoli_equivalent | 7,987.59 |
| toffoli_count | 7,735 |
| rotation_count | 37 |
| t_count | 1 |
| num_ops | 62,160 |
| reaction_depth | 4,005 |
| worst_error_over_tolerance | 0.477 |

**What it suggests:** the cost counts Toffoli-equivalents, so rotations add about 250 on top of the 7,735 Toffolis. Qubits multiply the whole cost, and 238 of the 260 are ancillas, so freeing ancillas is the biggest lever. The worst error is under half the tolerance, so there is precision to spend on fewer gates or qubits.
